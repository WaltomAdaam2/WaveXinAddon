# WaveXinAddon 功能逻辑说明

本页说明 ClickGUI 中公开模块的实现方式与需要注意的行为。它不是完整的设置手册；实际可用选项以游戏内模块设置为准。

### 杀戮光环+ (KillAura+)

- KillAura+ 是受本地许可证控制的可选模块。通过 `.wavexin redeem <code>` 验证后会立即注册到 WaveXinAddon 分类，但不会自动启用；它与 EndBaseFinder 使用相互独立的 Windows 本地加密许可证，每次启动都会重新验证。
- 战斗逻辑按 [Alienv4 Aura（e443c5b）](https://github.com/RageCat420/AlienClient-OpenSource/blob/e443c5bc499af722429d311333d10377623d6f9b/src/main/java/dev/luminous/mod/modules/impl/combat/Aura.java) 的行为独立适配，不加载 Alien 运行时。默认攻击距离 6、候选搜索距离 8、隔墙距离 6、冷却进度 1.1；候选搜索距离只决定显示和选取范围，不扩大实际攻击距离。
- 可分别筛选玩家、生物、动物、村民和史莱姆，排除好友，并支持距离/生命值排序、低护甲玩家优先、延时或原版冷却、TPS 换算、受伤时间限制及客户端/服务端挥手方式。`Weapon Only` 默认启用，只允许剑、斧、三叉戟。
- 模块会在玩家死亡、打开界面、Blink 启用、当前物品不符合武器限制，或禁止使用物品时玩家正在使用物品的情况下暂停并清空目标。异步转向后的攻击还会重新检查模块、世界、目标和距离。
- 渲染支持填充、方框、环形动画、Meteor 三维十字适配和关闭显示，并提供命中颜色、动画时间和缓动曲线。三维十字是对原 ThunderHack 显示的 Meteor 适配，不是原着色器效果的逐像素复刻。

### 鞘翅飞行 (Better Elytra Fly)

- 在鞘翅飞行期间接管水平与垂直运动计算，根据移动按键、视角和速度设置调整速度。显示为“初始速度”的 `Flight Speed` 保留原有配置键，默认值为 1.8；`Descent Speed` 保持原有范围不变。
- 独立的 `Speed Acceleration` 设置组默认关闭，关闭时保持固定速度行为。开启后仅在实际滑翔时间内按“每秒增加速度”递增，最大速度始终不低于初始速度；停止滑翔并再次开始时会回到初始速度。
- `Disable Acceleration While Ascending` 默认关闭；开启后，上升期间不会继续增加当前速度，但如果进入上升前已经达到最大速度，会以该速度继续上升。
- 启用 `Reset After Lagback` 时，收到服务端位置修正会回到初始速度并保持 5 秒，随后才继续渐进加速；关闭时不因修正包改变速度。
- 模块内的 `Elytra Replace` 设置组可单独启用自动更换：当已装备鞘翅的剩余耐久达到阈值时，从背包中寻找剩余耐久高于阈值的备用鞘翅并装备到胸甲栏。
- 自动更换可限制为仅滑翔时执行；找不到备用鞘翅时使用冷却警告，避免每个游戏刻刷屏。
- Inventory Tweaks 兼容选项会在更换期间暂时关闭该模块，并在设置的延迟后恢复，避免库存操作冲突。

### 鞘翅路径飞行 (Elytra Fly Path)

- 使用 Target X 和 Target Z 计算二维目标方向，并在滑翔时自动调整视角与移动速度向目标前进。
- `Nether Pos Calculation` 启用后会将输入的 X、Z 分别除以 8，再作为实际目标坐标。
- 到达范围由 `Arrival Distance` 判定；若同时启用自动停止和自动断开，会先停止模块，再执行断开。
- 模块可自动起飞，并会在推荐高度外启动时给出提示；最终飞行速度使用与 Better Elytra Fly 相同的可选渐进速度设置。
- 可选的 Xaero 临时路径点会在模块启用时创建 `Elytra Path`（别名 `EP`）；下界换算开启时使用换算后的 X/Z，Y 使用启用瞬间玩家高度。路径点使用 Xaero 原生临时标记，不写入坐标文件，闪退或强制结束进程后不会在下次启动时恢复。停用或退服时从创建时的坐标集中移除同一对象，即使已切换坐标集也能清理；删除失败保留句柄供后续重试。Xaero 缺失或不支持所需 API 时跳过创建并提示，不中断飞行。旧版本已保存且缺少归属标记的同名点不会被批量删除。

### 鸡标签名显示与嗅探兽标签名显示 (Chicken Nametags and Sniffer Nametags)

- 在 2D 渲染阶段为鸡或嗅探兽投影自定义名称牌。
- 名称牌可显示实体名称、生命值和距离，并受渲染范围、缩放、背景和文字颜色设置控制。
- 仅绘制匹配实体类型且处于设置范围内的实体，不修改实体数据或服务端状态。

### 自动登录 (Auto Login)

- 只在启用服务器限制且当前地址匹配 2b2t.xin 支持地址时运行自动化流程。
- 监听标题、副标题和聊天文本，检测登录提示后才处理离线账号的 `/l`；Microsoft 账号不会发送该命令。
- 账户记录按当前账户名保存。离线账号密码以加密形式保存，不会在聊天、状态或账户列表中回显。
- 登录成功后按状态机处理每日小红花签到、加入游戏和后续右击操作；每个阶段有延迟、重试和连接重置保护，避免重复发送或操作旧界面。

### 聊天过滤 (Chat Filter)

- MSG 私聊、公共聊天和死亡消息分别按各自设置过滤，过滤判断使用完整消息文本。
- `MSG Allowlist` 和 `Public Message Allowlist` 使用独立玩家列表；某个玩家加入其中一个列表不会同步到另一个列表。
- 白名单使用和 Meteor Friends 页面类似的列表输入：已有玩家按行显示，右侧 `-` 删除，底部输入框配合 `+` 添加。
- `Hide Death Messages` 使用最朴素的死亡公告格式匹配，例如自杀、床/烟花/TNT 自爆、末影珍珠死亡、世界边界自杀、环境死亡、玩家击杀、射杀、火球、窒息、坠落物砸死、推下悬崖或虚空等中英文格式；它不再依赖颜色组合，因此不会因为服务器其他彩色消息误过滤。
- 公共聊天只按已验证的单行 `<玩家名> 消息` 结构判断；`玩家名: 消息`、命令帮助、玩家查询、插件状态、服务器公告和 MSG 私聊都不会按 public 过滤。`Show Own Public Messages` 默认启用，会同时比较账户名和去格式/前缀后的显示名。

### 容器记录器 (Container Recorder)

- Container Recorder 是独立的常驻模块，以玩家周围的 `Scan Radius`（默认 4 区块）检查已加载区块；仅在符合容器类型筛选且数量达到 `Container Threshold` 时记录坐标和数量。
- 容器类型可在设置中选择，阈值默认 10。每 20 tick 复查附近已加载区块，区块数据到达时也会立即重新检查；切换世界时清理本次会话的检查缓存，避免把旧世界状态带入新世界。
- 模块保留可选的末影珍珠检测、文件记录、Xaero 路径点、原版成就提示框及挑战完成提示音。Xaero 默认关闭，区域半径默认 5、每区域最多 3 个基地点；珍珠点可独立选择是否写入记录。手动启用时模块独立运行，不依赖任何扫描模块。
- 容器记录保存在 `meteor-client/wavexin/container/container-records.txt`；首次使用新路径且文件不存在时，会迁移旧 `meteor-client/base-finder-xin/container-records.txt`。写入或路径点保存失败的待处理项会保留并重试，不会先把对应区块永久标记为成功。
- Base Finder 的普通扫描、螺旋扫描和 EndBaseFinder 都有独立的 `Start Container Recorder` 开关。扫描真正开始后才请求启动记录器；多个扫描同时请求时，记录器会等最后一个请求结束才自动关闭，即使玩家原本手动开启也一样。未启用联动的扫描不会取得记录器的关闭权。

### 基地狩猎扫图 (Base Finder)

- `普通扫描`从起始区块向外按环扫描，在目标之间移动，并可等待区块加载。每完成一圈只输出一条简洁消息。Restart 字段保持为可编辑的 Meteor 设置；启用`恢复上次扫描`后，直接使用填写的环数、路线、起点和断点值恢复。Base Finder 停用时会保存一次当前断点并同步更新这些字段，不会每 tick 刷新；若在返回已保存断点途中停用，则保留原断点而不写入途中位置。从设置界面或快捷键停用均使用同一流程。Restart 的重置按钮会清除已保存的普通扫描重启数据。
- `Spiral Scan` 使用独立的螺旋路线、步长、段数和渲染设置；自动走路时会持续朝当前目标区块中心修正方向，偏到目标区块边缘时先拉回中心再进入下一段。`Lock View` 开启时可见视角会锁向当前目标，关闭时仍会临时转向完成自动导航但每 tick 恢复玩家原视角；可选冲刺和打开界面时暂停。它不复用 Normal Scan 的断点逻辑。
- 普通扫描会在玩家经过区块的当个游戏刻记录为已访问，并让已访问颜色优先于当前路径颜色，因此无需等到下一次转向才变绿。普通扫描渲染距离默认 128 区块、上限 256 区块，预加载环数默认 10、上限 20。返回保存断点期间，该断点区块使用默认 `#E0B0FF` 的独立可调颜色高亮；到达后立即恢复普通路径颜色。
- 两种扫描可通过各自的 `Start Container Recorder` 设置联动独立的 Container Recorder。普通目标中心修正是正常移动状态，不写 warn；`BaseFinderDebug` warn 仅用于玩家/世界缺失、等待当前区块等异常或需要诊断的状态。
- Xaero 路径点为可选功能。仅在开启该选项时检查 Xaero Minimap；缺失时会关闭该选项并给出聊天警告，普通容器记录仍可用。基地路径点名称可使用数字、前缀和后缀，并按区域半径与每区域上限去重；`Area Radius` 默认 5，`Waypoints per Area` 默认 3。`Record Thrown Pearl` 会创建不限数量的 `Pearl 1`、`Pearl 2` 路径点，别名为 `P1`、`P2`，使用同一个路径点颜色设置，并且不计入基地的每区域路径点上限。创建成功的聊天提示会保留 WaveXin 前缀，并将路径点名称加粗、使用 Xaero 实际的 0–15 颜色编号对应色显示；随机颜色只生成一次，同一个编号同时用于路径点和聊天提示。

### 末地折跃门定位 (EndBaseFinder)

- EndBaseFinder 是受本地许可证控制的可选模块，只会在末地开始，并根据输入的世界种子在本地预测末地返回折跃门。`Generation Version` 默认为 1.12，也可选择 1.20.4 或同时扫描两种规则；预测结果不会替代已加载区块中的实际方块确认。
- `Rolling Radius (Chunks)` 定义整个圆形工作范围，默认 1,000 区块、范围 8–100,000。`Calculation Batch (Chunks)` 默认 3,000,000、范围 1,000,000–100,000,000；后台单线程以完整的 32×32 区块 Tile 从中心向外分批处理，因此实际单批最多比预算少 1,023 区块。发现首个可用候选后即可开始路线，不等待整个半径完成。
- 每批计算结束后保留调度游标并显示 `Queued`。当已计算但尚未到达的折跃门不超过 10 个且范围仍有未计算 Tile 时，会排入下一批；第一批没有候选时也会继续。只有整个圆形范围都处理完才显示 `Complete`，新增结果不会抢占仍然有效的当前目标。
- `Fixed Scan Center` 默认关闭，此时每次启用以玩家当时位置为中心；玩家距当前工作圆边缘 100 格时，中心推进到玩家位置并复用重叠 Tile。固定中心开启后使用可配置的 X/Z，范围完成后不随玩家推进；模块运行期间中心模式及 X/Z 被锁定，需先关闭模块才能修改。
- 计算缓存只保存在当前游戏会话内，并按世界实例、种子、生成版本、中心和半径隔离；相同配置关闭后再开启可复用重叠结果，切换世界或关键参数不会串用。右上角独立进度提示在模块启用期间常驻，动态显示 `Scanning`、`Queued`、`Next Area`、`Complete` 或 `Failed`、已计算/总区块及百分比、已到达/已发现折跃门及百分比。
- 已访问折跃门按种子统一保存在 `meteor-client/wavexin/end-gateways/`。启用时会立即把当前工作范围内的历史记录计入已到达数量；本次计算期间实际抵达的点也同步计入。聊天中的 `Arrived At #N -> (x, z)` 使用这个累计数量，不会从 `#1` 逐条补报历史记录；当历史数量暂时大于已发现总数时，Toast 百分比封顶为 100%。
- Base Finder、Elytra Fly Path 与 EndBaseFinder 互斥；其中任一已启用时，另外两个会拒绝启动并在聊天框提示。Base Finder 与 EndBaseFinder 启用期间会像 Elytra Fly Path 一样屏蔽玩家的 WASD、跳跃和潜行输入，停用后恢复物理按键状态。
- 支持最近邻、TSP、扫描顺序和随机四种路线算法；默认自动看向目标，到达距离为 16 格，可选到点停留。默认颜色为当前目标橘色、1.12 预测绿色、1.20.4 预测红色、已完成蓝色，全部可修改；默认渲染距离为 1,024 格。
- 在模块确认末地并开始扫描后，`Start Container Recorder` 默认联动启动独立的 Container Recorder。批次暂停为 `Queued` 或当前范围完成时不会释放记录器；只有 EndBaseFinder 最终停用或启动失败时才结束自己的请求并按联动所有权关闭记录器。

### 投影打印机 (Litematica Printer)

- Printer 是半自动 Builder：模块不会替玩家自动寻路、挖掘或搭路。玩家自行移动到施工位置后，Planner 只选择客户端已加载、位于交互距离内、拥有六面真实相邻支撑且当前可以正确交互的投影目标。旧的 Baritone 和挖掘适配代码仍保留在项目内，但不进入当前运行路径。
- 放置执行器合并了三类成熟行为思路：Scaffold 的连续支撑面放置、Alien Client Surround（围脚）的发包式 multi-place 与快捷栏静默切换，以及 Mio Surround（围脚）的邻近支撑优先。这里是行为模型的重新实现，不是运行时依赖 Alien/Mio，也没有把这些客户端整体嵌入 WaveXinAddon。
- `PrinterBatchPlanner` 是高亮和下一次放置的唯一决策源。每批默认最多 3 个目标，按稳定坐标、玩家距离、材料可用性和真实支撑确定顺序；绿色框显示的目标与实际待执行 batch 相同。黄色框表示已进入重试等待间隔、仍会在下一失败轮重新检查的目标；红框表示需玩家手动修正的状态。依赖方向或形态的方块不会使用尚未被服务器确认的同 tick 虚拟支撑。
- 放置会精确比较目标 `BlockState`。漏斗根据目标输出方向选择点击面；成对箱子按朝向和 `LEFT/RIGHT` 状态作为一个逻辑 pair 放置，临时单箱不会被记为完成。无法自动修复的错误朝向或错误箱子使用红框等待玩家手动处理，不会让模块随机拆方块。
- 对容器和其他可交互支撑进行放置时，Printer 在服务端临时潜行，并仅在确实需要时发送临时 yaw/pitch；交互结束后立即恢复服务端朝向，本地镜头不被修改。Printer 自己误开的容器界面会在短保护窗口内关闭，玩家手动打开和补货所需界面不受影响。
- 建造材料始终先按快捷栏从左到右查找。启用 `Allow Inventory Pull` 后，仅在快捷栏缺少对应材料时，才按背包从左到右、从上到下选取完整 stack 换入快捷栏，避免每次放置都临时搬动物品。
- `.sel`、`.sel 1`、`.sel 2` 选择补货长方体，`.sel c` 清除两个端点、渲染和该区域的容器缓存。补货按当前 Litematica layer/range 或当前可施工范围统计需求，优先填充近期目标且需求量较大的材料，并从容器按整组拿取；不会自动把玩家物品退回容器。背包需要人工清理时会停用模块，重新启用后从会话缓存继续。
- 投影目标和已观察容器使用世界、投影指纹、区域及状态摘要绑定的会话缓存。模块关闭不会清除进度；退出世界或游戏时清理。模块启用后立即扫描已加载的投影区块和补货容器，其余部分在玩家靠近并加载后补齐，缓存不能代替最终已加载状态确认。
- 使用 `.wavexin debug printer on/off` 控制诊断日志，文件位于 `meteor-client/wavexin/debug/[LitematicaPrinter]-yyyy-MM-dd-N.log`。日志记录 planner、支撑、状态、临时旋转、界面拦截、补货、缓存和 audit 决策，并合并重复事件、批量写入以减少开销。
- `Maximum Projection Volume` 默认 10,000,000，硬上限 500,000,000。提高上限只允许扫描更大的边界，不代表一次性加载；扫描仍受每 tick 预算、区块加载和内存约束。液体、生物、实体、含水状态及无法可靠放置的结构会在其他可施工方块完成后统一报告。

### 指令、访问权限与数据文件

- Meteor 指令前缀可由用户修改；本文用默认的 `.`。`.wavexin redeem <code>` 是可选模块的唯一兑换入口：输入只参与本地摘要匹配，不写入日志或明文文件；成功后对应模块立即注册但保持关闭。EndBaseFinder 与 KillAura+ 分别使用 `license.dat` 和 `killaura-license.dat`，许可证由 Windows 当前用户的本地加密能力保护，不能互相解锁。
- `.wavexin check-update true|false` 保存启动时更新检查开关；`.wavexin lang Chinese|English` 只切换 WaveXinAddon 自身文本；`.wavexin debug <module> on|off` 控制模块日志；`.sel [1|2|c]` 选择或清除 Printer 补货区域。
- `meteor-client/wavexin/settings.json` 保存 WaveXinAddon 全局偏好，`scan-progress.json` 保存 Base Finder 断点，`container/container-records.txt` 保存容器记录，`end-gateways/` 保存按种子隔离的到达历史。EndBaseFinder 的 Tile 与候选缓存只存在于当前游戏会话，不写入磁盘。
- 升级不会把旧 `settings.json` 中的激活标记或旧许可证迁移为当前许可证；没有有效许可证时，受控模块不会注册。许可证与兑换内容不包含在普通设置、聊天、更新请求或诊断日志中。

### 更新检查与诊断日志

- 启动更新检查默认开启，仅后台读取公开的 GitHub Releases 版本信息，不自动下载或安装，也不上传账号、玩家、服务器、HWID、种子或配置。直连 GitHub 失败时按顺序尝试 `ghfast.top`、`gh-proxy.com` 和 `gh.3w.pm`；它们是第三方公开代理，可用性不由本项目保证。
- 统一调试命令支持 `autologin`、`basefinder`、`elytraflypath`、`container`、`printer` 和 `endbasefinder`。日志分别写入 `meteor-client/wavexin/debug/[Module]-yyyy-MM-dd-N.log`，不同模块和同日多次会话使用独立文件。
- 调试写入会合并重复 INFO 事件并批量刷新，以降低长期运行的磁盘与主线程开销；错误与重要状态仍会及时写入。日志用于模块诊断，不记录兑换输入或已保存密码。

### 性能与生命周期

- 全插件设置每 20 tick 检查一次变更；界面切换、退服及正常退出时立即补存。写入失败不会更新已保存标记，后续检查会重试。强制结束进程可能丢失最近约一秒内的设置变更。
- 容器扫描使用原始长整数区块键，先跳过缓存命中，再访问区块管理器；原有每 20 tick 复查、容器阈值与记录格式不变。
- EndBaseFinder 只使用一个后台计算线程，并按 32×32 区块 Tile、可配置预算和最多每秒一次的批量结果发布控制开销；大半径代表长期增量任务，不代表一次性分配或计算整个圆形范围。
- 鸡与嗅探兽标签在范围不超过 256 格时使用按类型的空间查询，距离筛选使用平方距离；超大范围回退到实体遍历，避免枚举大量空空间。
- 鞘翅路径飞行合并每次移动的速度写入，保留原速度和阻尼计算；自动登录每次重新启用都会重查当前服务器，避免停用期间切服后沿用旧判断。

### 双语实现 (Bilingual Implementation)

- WaveXin 可见文本使用 Minecraft 原生 `assets/wavexin/lang/*.json` 资源；默认随客户端语言选择简体中文或英文兜底。`.wavexin lang Chinese` 和 `.wavexin lang English` 可保存 WaveXinAddon 自身的显示语言覆盖，不会修改 Minecraft、Meteor 或其他 addon 的语言。
- 翻译只影响显示文本；`Module.name`、`Setting.name`、`SettingGroup.name`、enum 常量、NBT 和配置值都保持原始标识符，因此切换语言不会改写已保存设置。
- ClickGUI 的模块卡片、模块页面、设置组、设置标题与描述、enum 下拉框、自定义按钮、搜索结果和 Active Modules HUD 通过 WaveXin 专用 i18n 辅助方法显示当前语言文案；非 WaveXin 的 Meteor 模块保持上游行为。
- 聊天消息、警告、调试状态、断开原因和实体默认名称使用相同翻译层，并保留 Java Formatter 占位符和 Meteor 聊天样式 token。
- `verifyWaveXinTranslations` 会校验 `en_us`/`zh_cn` key 集合、显式 expected-key registry、静态 Java key、dead key、占位符、Meteor token、mojibake 和非法值；`testWaveXinI18nBehavior` 覆盖 fallback 格式化、keySegment 和 null enum 兜底。
- `testWaveXinUiTranslationCoverage` 会按当前源码写法从已注册模块推导设置与枚举选项的显示键，不启动 Minecraft；遇到无法识别的设置声明会校验失败。非 Meteor 主题保留自身下拉控件并显示翻译标签，保存的枚举值不变。
